# 動画と記事をセットで運用する

題材は本人の非公開の学習用Markdown。そこから一つの学習目標に対して、動画と復習記事を一組で編集する。記事は台本の全文転載ではなく、会社類型・要件の比較、例外、答えを隠した再テストを受け持つ。

## 対応の管理

`sources/video-notes.json` を lesson ID → 公開記事URL の正本とする。動画IDは `state/youtube.json` のアップロード結果から取得する。既存登録の `videoId` と食い違う場合は止めて確認し、再アップロードで解決しない。
法令改正時は動画・記事双方の確認日と対象範囲を見直す。記事が動画より新しくなったら、その差分を記事の動画節にも明記する。

## 毎回の流れ

1. 原本の該当節と一次資料から、学習目標・事例・比較表・再テストを設計する。
2. 対応記事をLearning OSに作り、公開URLを対応表へ登録する。動画未投稿の段階では存在しない動画リンクやプレーヤーを置かない。
3. `memory:prepare` は概要欄の先頭へ記事URLを入れる。投稿処理も最新の対応表からリンクを補うため、古いレンダリング成果物でも概要欄のリンクを落とさない。
4. 非公開アップロードの結果を保存する。同じ動画IDを使って `node scripts/memory/note-link.mjs <lesson-id>` を実行する。投稿workflowも自動でこのファイルを作る。
5. 出力された `out/<lesson-id>/note-link.md` の「対応動画」節を対応記事に反映する。毎回追記して重複させず、その節を更新する。研究packetから公開される記事はpacketが本文の正本なので、通常のupsertで見えない本文だけを変更しない。既存記事の単独YouTubeリンクはそのままプレーヤーになる。
6. `node scripts/memory/note-link.mjs <lesson-id> --check` で公開記事のHTTP成功と一致する動画IDのプレーヤーを確認する。Studioでも実動画の概要欄URLを確認する。埋め込み検証と再生可能性は別に記録する。
7. 動画を公開する際は、既存IDの設定変更後に記事の「非公開試作」などの案内を更新し、ログインしていない読者として再生できることまで確認する。

## 記事側の表示

司法書士公開ノートの本文で、一行だけの `[動画の題名](https://youtu.be/動画ID)` または通常のYouTube watch URLを置くと、レスポンシブな16:9プレーヤーに変わる。文中の通常リンクはそのまま。任意のHTMLを許可せず、対象は正規のYouTube URLと11文字の動画IDに限定する。YouTubeで直接開くリンクも残す。
記事は「対応動画 → 判断軸・比較表 → 注意点 → 確認問題 → 答え合わせ → 根拠」を基本とする。必要なら動画チャプターへの時刻リンクも付ける。
